# 検証の範囲

## 自動テスト

開発用のテストではNode.jsとPython 3を使用します。一般のVSIX利用者にPythonは不要です。

```sh
npm test
```

テストの対象：
- JSONの大きい数値・重複キー・文字列内空白・エスケープの保持
- 完全一致ログの集約、時刻・数値・検出した重要行の保持
- preview の情報落ちの明示
- 原文保存、引用の文字列一致／不一致、ハッシュ不一致、最新ファイルの変更検知
- 日本語・絵文字・BOM・CRLF・長い1行のページ取得
- パストラバーサル、秘密ファイル、シンボリックリンク、サイズ上限、不正な入力
- 期限切れ、キャッシュ容量上限、内容改変、明示削除
- MCP初期化・ツール呼び出し・実プロセスのstdio通信
- CLIの設定JSON生成・エラー終了・統計
- 圧縮前後のバイト数・文字数・削減率、原文再取得の追加分、0サイズ・旧形式の扱い
- 本文未表示を100%圧縮として扱わないこと、実トークン・料金を未計測と表示すること
- リポジトリ単体の試用設定と6つのプロンプトの整合性

これらはプログラムの機械的な動作テストです。要約の正確さや、主張が原文から妥当に導かれることを自動保証するものではありません。

## 共通知識の機械的な検証

- 台帳の項目・状態・版・範囲・ID・相対パスの検証
- 一覧でのローカルな変更検知を本文出力として扱わないこと
- 登録のみ／原文の場所のみ／部分出力／全体出力を区別すること
- 文字・行の範囲を同一原文・同一登録条件でのみ合算すること
- 本文や台帳の変更、原文保存版の期限切れ・不一致を再確認とすること
- 不正な台帳・壊れた出力記録・ルート外リンク等を黙って確認済みにしないこと
- purge で登録Markdownを消さず、出力記録だけをリセットすること

意味的な矛盾の完全自動検出・AIの理解・利用者の承認・正式資料の真実性を保証する試験ではありません。

## 初期設定拡張の自動テスト

- 計画段階・入力取り消し・最終確認の取り消しでは、ファイルを作成しない。
- 既存資料・台帳・プロンプトを維持し、再実行を不要な重複作成にしない。
- 選んだ設計書をコピーせず相対パスで登録する。ルート外・秘密パス・大きすぎる入力等を拒否する。
- `.gitignore` の既存内容・改行・パーミッションを保持し、先行する否定ルールより後に除外を置く。
- 計画後の競合を作成前に検出し、途中失敗時は自分が新規作成した未変更のファイルだけを戻す。
- 内蔵HTTPの認証・Host/Origin・形式・容量上限・停止・要求直列化を確認する。
- 模擬VS Code APIでチャット起動→確認→保存→MCP登録→実HTTPツール呼び出し→停止・再開を確認する。
- 配布用ステージにコードと雛形だけが入り、テスト・私的キャッシュ・依存パッケージが混ざらないことを確認する。

**APIの模擬テストは、実際のVS Code UI・Copilot連携の検証を代替しません。** VSIXは公式 `@vscode/vsce` をGitHub Actionsで実行して生成する構成です。現時点では自動配布設定の追加権限が不足し、ActionsでのVSIX作成・公開は未実施です。初回公開後にビルドの成否をActionsとReleasesで確認します。

## 配布前に確認した環境

ローカルでは macOS / Node.js 24 で確認しています。Linux・Windows・Node.js 20/22/24の組み合わせはCIで検証する構成ですが、CIの実行結果がない環境では対応済みとは扱いません。VS Code本体・実際のCopilotセッションには接続していません。
テスト件数・結果は同梱の `TEST-RESULTS.txt` を参照してください。
Windows等でシンボリックリンク作成の権限がない場合、該当テストはスキップします。スキップは保護機能を検証できたという意味ではありません。
CIでスキップが発生した場合も、passとは別にskipped件数として記録します。

## ご友人の環境での受け入れ確認

- [ ] ReleasesからVSIXを取得し、VS Codeの「VSIXからのインストール」で追加できる。
- [ ] `@contextkit 初期設定` で入力欄が開き、確認後にだけ設定される。
- [ ] 取消し・既存の資料を残した再実行が意図どおり動く。
- [ ] VS CodeのMCP一覧で Context Kit（拡張内蔵）またはCLIの context-kit が起動する。二重接続しない。
- [ ] 設定済みのフォルダを開き直したとき、接続が復元される。
- [ ] 圧縮状況・用語集／設計書のボタン・停止操作が使える。
- [ ] 実際のツール実行欄で kit_read と kit_source の返却が見える。
- [ ] 引き継ぎメモに確定事項・例外・未確認事項が分離される。
- [ ] 引き継ぎ前に利用者がメモを確認できる。
- [ ] 利用者が開いた新しいチャットでメモを読み、重要な根拠へ戻れる。
- [ ] 出典が取れないとき、未確認と明示して推測で断言しない。
- [ ] 元ファイルを変更したとき changed を確認し、保存版を最新と誤認しない。
- [ ] 短い会話・小さい資料で、メタ情報や原文確認のコストが上回る場合も分かる。
- [ ] 実案件で総利用量と成果品質を比較する。削減率・精度向上率はその比較後に判断する。
