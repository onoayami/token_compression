# 検証の範囲

## 自動テスト

```sh
node --test test/core.test.mjs test/server.test.mjs test/cli.test.mjs test/stats.test.mjs
```

テストの対象：
- JSONの大きい数値・重複キー・文字列内空白・エスケープの保持
- 完全一致ログの集約、時刻・数値・検出した重要行の保持
- preview の情報落ちの明示
- 原文保存、引用の文字列一致／不一致、ハッシュ不一致、最新ファイルの変更検知
- 日本語・絵文字・BOM・CRLF・長い1行のページ取得
- パストラバーサル、秘密ファイル、シンボリックリンク、サイズ上限、不正な入力
- 期限切れ、キャッシュ容量上限、内容改変、明示削除
- MCP初期化・ツール呼び出し・実プロセスのstdio通信
- CLIの設定JSON生成・エラー終了・統計
- 圧縮前後のバイト数・文字数・削減率、原文再取得の追加分、0サイズ・旧形式の扱い
- 本文未表示を100%圧縮として扱わないこと、実トークン・料金を未計測と表示すること
- リポジトリ単体の試用設定と4つのプロンプトの整合性

これらはプログラムの機械的な動作テストです。要約の正確さや、主張が原文から妥当に導かれることを自動保証するものではありません。

## 配布前に確認した環境

Linux / Node.js 24。VS Code本体・実際のCopilotセッションには接続していません。
テスト件数・結果は同梱の `TEST-RESULTS.txt` を参照してください。
Windows等でシンボリックリンク作成の権限がない場合、その2件はスキップします。スキップは保護機能を検証できたという意味ではありません。

## ご友人の環境での受け入れ確認

- [ ] VS CodeのMCP一覧で context-kit が起動する。
- [ ] 実際のツール実行欄で kit_read と kit_source の返却が見える。
- [ ] 引き継ぎメモに確定事項・例外・未確認事項が分離される。
- [ ] 引き継ぎ前に利用者がメモを確認できる。
- [ ] 利用者が開いた新しいチャットでメモを読み、重要な根拠へ戻れる。
- [ ] 出典が取れないとき、未確認と明示して推測で断言しない。
- [ ] 元ファイルを変更したとき changed を確認し、保存版を最新と誤認しない。
- [ ] 短い会話・小さい資料で、メタ情報や原文確認のコストが上回る場合も分かる。
- [ ] 実案件で総利用量と成果品質を比較する。削減率・精度向上率はその比較後に判断する。
