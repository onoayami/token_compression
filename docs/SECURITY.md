# 安全性・プライバシー・限界

## 保護している範囲

- 読み取り対象は設定したルート内の通常のUTF-8ファイルに限定。
- ルート外へのパストラバーサル、ルート外を指すシンボリックリンク、代表的な秘密ファイル名、キャッシュ自体、未対応拡張子を拒否。
- 原文は `.context-kit-cache/` 内に保存。作成時のUnixパーミッションはディレクトリ700・ファイル600。Windowsでは同等のACLを保証しない。
- 原文の内容とSHA-256を照合し、期限切れ・取得失敗・不一致を明示。
- MCPへ返す自前エラーは `FILE_NOT_FOUND`、`ACCESS_DENIED`、`BLOCKED`、`TOO_LARGE`、`INVALID_ARGUMENT`、`CONTEXT_KIT_ERROR` の許可リストに限定し、メッセージは固定文言です。詳細（入力値・パスを含む場合があります）はstderrの診断ログだけに出します。
- 共有ボリュームを別コンテナ・別PID名前空間から同じキャッシュへ同時接続する構成はサポート対象外です。hostnameが同じでもPID判定が分離され、ロックの生存確認を誤る可能性があります。
- 独自の外部AI API・認証情報の取得・任意コマンド実行・テレメトリーは実装していない。CLIのMCP通信はstdio。拡張版のみ127.0.0.1の一時ポートで認証付きHTTPを使う。
- 圧縮・原文取得ツールは元の入力ファイルを変更・削除せず、キャッシュ・統計・本文出力記録を作成する。
- 初期設定は利用者の確認後に、不足する雛形とプロンプトを作成し、`.gitignore` へ除外ルールを追記する。既存の資料・台帳・プロンプトは上書きしない。
- `kit_source` もアクセス統計を書くため、副作用があるツールとして宣言している。

## 保護しない範囲

- **通常のログやMarkdownに含まれるAPIキー・個人情報等は自動で完全検出・秘匿しない。** 読む前に確認し、必要ならマスキングすること。
- 保存版は暗号化しない。クラウド同期・バックアップ・他プロセスからのアクセスを自動で止めない。
- 同じユーザー権限の悪意あるローカルプロセス、ファイル差し替えの競合、ハードリンク等まで防ぐセキュリティ境界ではない。信頼したプロジェクトでのみ使う。
- モデルがツール出力を読んだ後は、通常の Copilot のサービスへその内容が送信され得る。「ローカル処理」は「Copilotにも一切送られない」という意味ではない。
- プロンプトインジェクションを機械的に完全検出する機能はない。資料内の命令を実行しないようプロンプトで注意するが、それだけで安全は保証しない。
- 保存ファイル内のSHA-256は自己申告値であり、単独では改ざんを検出できない。偶発的な破損の目安にはなるが、改ざん対策には `kit_read` が返したSHA-256を呼び出し側で保持し、`kit_source` の `expected_sha256` で照合する。照合なしの取得は `self-reported-only`、一致時は `matched-external-expected-hash` と表示する。
- 引用の一致は文字列の存在を示すだけ。因果・条件・例外・結論の正しさまでは検証しない。
- 会話の内容はMCPから自動取得できない。要約の根拠が会話のみなら、元記録がない限り利用者による確認が必要。

## 保持期間

原文保存版は既定で7日間（168時間）。容量上限は保存版合計64 MiB。
新しい保存版を作るときに期限切れや古い保存版を整理する。取得時も期限を確認する。
**7日経過時にバックグラウンドで自動削除する常駐機能はない。** 完全に消したい場合は `purge` を明示実行する。
容量上限により7日より前に消える場合もある。出典が消えたら「根拠切れ」と扱い、推測で埋めない。
統計は直近のものだけを最大約1 MiB保持し、本文・パス・引用を記録しない。
`purge` は原文保存版・統計・共通知識の出力記録のみ削除し、元ファイル・引き継ぎメモを削除しない。

## 使う前の確認

1. 拡張版は配布元と作成予定の内容・対象フォルダを確認。CLI版はNodeの実行先、起動引数、対象ルートを確認。
2. `.context-kit-cache/` と `.context-kit/` がプロジェクト直下の `.gitignore` で除外されているか確認。既にGit追跡中のファイルは、除外ルールの追記だけでは追跡解除されない。
3. 実データではなく同梱の架空データで接続確認。
4. 自動承認は最初から有効にせず、ツールの入力と返却内容を確認。
5. 原文再取得・ハッシュ不一致・根拠切れの動作を確認してから業務へ使う。

この試作は本番品質・セキュリティ監査済み・ハルシネーション防止を保証するものではありません。


## 共通知識の登録と記録

登録した資料の一覧には、名前・場所・宣言上の状態・版・適用範囲などの情報が含まれます。資料名や場所も機密になり得ます。
一覧の変更検知はローカルで行い、本文を出力したこととは分けます。実際のAI受信・理解・真実性を検証する仕組みではありません。
出力記録は `.context-kit-cache/context-reads.json` に原文のハッシュ・出力範囲・登録条件・保存版IDを保存します。原文本文の複製をさらに作るものではありません。
この記録は原文の7日期限とは別に、明示削除まで残る場合があります。原文保存版の期限切れは再確認として表示します。`purge` で記録も削除できます。
実資料をGitHubへ公開しないよう、登録するファイルとリポジトリの公開範囲を利用者が確認してください。

## 拡張版のローカル接続と初期設定

- 内蔵HTTPサーバーは127.0.0.1のみで待受し、外向き公開アドレスでは待受しない。
- 起動ごとのランダムなBearerトークンを照合する。拡張はこのトークンを設定ファイルへ保存しない。VS Codeには接続ヘッダーとして渡す。
- HostとOriginを制限し、JSON POSTだけを受け付ける。リクエストは64KiBまで。独立したSSEやバッチ要求は受け付けない。
- 信頼していないフォルダ・リモート環境での初期設定を拒否する。開いた作業フォルダを閉じると接続を停止する。
- 初期設定は計画→利用者の確認→作成の順で行う。確認前にはファイルを作成しない。計画後に作成先が変わっていれば中断する。
- 既存のMCP設定ファイルは書き換えない。旧接続との重複は警告し、停止は利用者が行う。
- 停止・拡張のアンインストールでは、資料・キャッシュ・引き継ぎメモを自動削除しない。必要な削除は利用者が行う。

同一ユーザー権限の悪意あるローカルプロセスまで防ぐものではない。GUI・Copilotとの実接続、Windows/macOS上の動作は利用環境での受け入れ確認が必要。
