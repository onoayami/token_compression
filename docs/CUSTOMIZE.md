# 友人向け：改造ポイント

## 実装の地図

```text
src/context.mjs    Markdown登録台帳・版・適用範囲・本文出力記録
src/core.mjs       圧縮・安全な入口・保存版・原文範囲取得・簡易統計
src/server.mjs     MCP共通ハンドラー・stdioサーバー（4ツール）
src/setup.mjs      初期設定の計画・確認後の作成処理
src/report.mjs     圧縮状況を日本語テキストに整形
src/cli.mjs        単体動作・設定の表示・統計・保存版削除
src/options.mjs    起動引数・任意設定ファイル
integration/      VS Code設定例・手動実行プロンプト
examples/         架空の入力・空の引き継ぎメモ
vscode-extension/ 初期設定チャット・コマンド・ローカルHTTP接続
scripts/          VSIX用ステージ作成（公式vsceへ渡す）
test/             単体・MCP・CLI・初期設定・模擬拡張APIテスト
```

会話の要約を作るのは Copilot です。Node 側は会話を自動取得せず、独自AIも呼びません。
引き継ぎメモの保存には Copilot 内蔵のファイル編集機能を使い、利用者が新しいチャットを開きます。
MCP側の読み取り用ツールは原文保存と読み取りに限定し、任意ファイル編集やコマンド実行の入口を増やしていません。

## 最初に変えやすいところ

1. `config.example.json` を自分用にコピーし、表示量・期限・追加の禁止パス・保護したい語を調整。
2. `integration/prompts/` に自分の業務で落としてはいけない要件を追記。
3. 実際によく出るログ形式のフィルターを `compact()` に追加。未知の形式は変更せず返す。
4. モデル用の tokenizer を必要に応じて追加し、バイト数とトークン数を混同しないよう別の指標として記録。

独自設定を使う例：

```sh
node src/cli.mjs config --root "/absolute/path/to/project" --config "/absolute/path/to/my-config.json" --format vscode
```

設定は起動時に明示的に指定します。例の設定ファイルが勝手に読み込まれることはありません。
秘密ファイル名等の基本ブロックを設定で無効化する機能は設けていません。

## 拡張時のルール

- フィルターが意味を変え得るなら、lossy の表示・原文への入口・省略範囲を付ける。
- JSON.parse → JSON.stringify で数値を再出力すると、大きい整数を壊す場合がある。この実装は原文の数値表記を保つ。
- 行番号は圧縮本文ではなく、保存した原文の位置にひも付ける。
- ハッシュを出典の正当性や電子署名と混同しない。ここでは文字列一致・取り違え検知の補助。
- quote_match が true でも、その文章が主張を論理的に支持するかは別問題。
- 原文保存の期限や容量を大きくすると、機密保持・容量管理の責任も増える。
- 保存版IDが増えるほどメモ自体のトークンも増える。同じ出典は台帳で一度だけ書き、要点側では短いIDを使う。
- キャッシュ保持期間より長い引き継ぎが必要なら、利用者の明示操作による「保存版の固定・解除」を別機能として設計する。この最小版にはない。
- 会話の根拠まで機械的に検証するには、利用者が保存した原会話記録などの信頼できる入力が必要。AI自身に生成させた会話の引用を証拠として採用しない。
- 参照先が変わったら、以前の根拠で最新仕様を断言しない。

## 評価の進め方

同じタスクを同じモデル・設定で、キットなし／ありで比較します。
見るのは「要約作成・根拠再取得・やり直しまで含めた総利用量」「最終成果の正確さ」「見落とした要件」「作業時間」です。
合成デモのログ圧縮率を、そのまま実プロジェクトの節約率として扱わないでください。
この配布物では、実タスクの比較評価やハルシネーション低減率の測定はしていません。

## いきなり追加しないほうがよい機能

Copilot の認証情報の読み取り、通信先の強制変更、非公開APIへの依存、全コマンドの自動実行、無断の全ファイル走査。
まず公式 MCP と手動の引き継ぎフローで対象の入口が使われているか確認してください。


## 共通知識の拡張

`project-context/catalog.json` が入口です。資料本文はMarkdownのままで、既存ファイルの相対パスも登録できます。
一覧取得は本文を返さず、明示的に選んだIDだけ読みます。プロンプトだけでなくプログラム側でも登録・部分出力・全体出力・変更後の再確認を区別します。
`src/context.mjs` の出力記録は同じ原文ハッシュ・同じ台帳条件でのみ範囲を合算します。

意味的な矛盾検出や、タスクを自動判定して読む資料を選ぶ参照セットは未実装です。初期版の範囲を広げる場合も、台帳の正式性を自動で書き換えないでください。

## 拡張版の開発・配布

1. `npm test` でコア・初期設定・模擬APIのテストを実行。
2. `python3 scripts/stage-extension.py` で `dist/extension/` を作る。既存の出力へは上書きしない。
3. Node.js 22以上のビルド環境で、公式 `@vscode/vsce@4.0.0` の `vsce package --no-dependencies` を実行。一般の利用者にはできたVSIXだけを渡す。
4. 実際のVS Code上で `docs/VERIFICATION.md` の受け入れチェックを実施。

`integration/release-vsix.workflow.yml` が配布設定のテンプレートです。現在の接続ではWorkflowsへの書き込みが403となったため、`.github/workflows/release-vsix.yml` としての登録は未完了です。[初回公開手順](FIRST-RELEASE.md) に沿って管理者が確認・登録してください。登録後はmainの拡張関連変更でテスト・パッケージ作成・GitHub Releaseを行います。実行にはActionsの利用と `contents: write` が必要です。既存の公開版は置換せず、次回はroot package・拡張manifest・サーバー表示・接続定義・テスト中の版を揃えて更新してください。Marketplaceへの自動公開は行いません。

拡張実行時には外部Node・npm・Python・vsceは不要です。127.0.0.1のサーバーはVS Codeの拡張ホスト内で動かします。リモート開発への対応を増やす場合、拡張の実行側とファイルの所在・アクセス範囲を先に設計してください。
