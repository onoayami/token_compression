# Copilot Context Compression Kit

GitHub Copilotで扱う資料を整理し、必要な部分だけを読み、あとから原文へ戻れるようにするためのツールです。

主な用途は次の3つです。

- 会話の区切りで、確定事項・未確認事項・根拠を引き継ぎメモへまとめる
- 用語集・要件・設計書などを台帳へ登録し、必要な資料だけをCopilotへ渡す
- ログやJSONを安全な範囲で整理し、要点から保存した原文へ戻れるようにする

## どう動くか

1. 初期設定で、資料の台帳、引き継ぎ用プロンプト、Context Kitを優先するCopilot用の指示を作ります。
2. 利用者は通常のCopilotへ、調査や実装を普段どおり依頼します。
3. Copilotが対応するログ・JSON・テキスト・Markdownを読む必要があると判断すると、`kit_read`を優先して呼び出します。
4. `kit_read`は、同じログ行の繰り返しやJSONの不要な空白をPC内で整理し、原文の保存版を残します。
5. 重要な数字や条件は、`kit_source`で保存版の原文へ戻って確認できます。

普段はツール名を毎回指定せず、次のように依頼できます。

```text
このログを確認して、エラーの原因を調べてください。
```

```text
登録してある要件と設計書を確認して、この変更の影響を教えてください。
```

初期設定で追加される指示により、CopilotはContext Kitの利用を優先します。
ただし、最終的なツール選択はCopilotのモデル判断と実行許可にも左右されます。

## かんたん導入

ローカルのデスクトップ版VS Codeでは、`contextkit.vsix`をインストールする方法が簡単です。
外部Node.jsのインストール、ターミナル操作、MCP設定JSONの手編集は必要ありません。

### 必要な環境

- VS Code 1.102以降のデスクトップ版
- 利用可能なGitHub Copilot
- VS Codeで開いた、信頼済みのローカル作業フォルダ

WSL、Remote SSH、Dev Container、ブラウザー版VS Codeでは拡張版を使用できません。
これらの環境では、後半の「CLI方式で接続する」を使用してください。

### インストール

1. GitHub Releasesの最新リリースから `contextkit.vsix` をダウンロードします。
2. VS Codeの拡張機能画面を開きます。
3. 画面右上の「…」から「VSIXからのインストール」を選びます。
4. ダウンロードした `contextkit.vsix` を指定します。
5. インストール後にVS Codeの再読み込みを求められた場合は、再読み込みします。

`Source code.zip` はインストール用ファイルではありません。

## 初期設定

1. 設定したいプロジェクトの**フォルダ**をVS Codeで開きます。
2. Copilot Chatで `@contextkit 初期設定` と入力します。
3. プロジェクトの目的を一言で入力します。空欄でも先へ進めます。
4. 既存のMarkdown設計書があれば選びます。ない場合は「あとで記入する」を選びます。
5. 作成・追記される内容を確認し、「設定する」を選びます。
6. MCP接続の信頼確認が表示された場合は、内容を確認して承認します。

初期設定では、足りない資料・台帳・プロンプトだけを追加します。
既存の資料、台帳、プロンプトは上書きしません。
選択した設計書はコピーせず、元の場所を台帳へ登録します。

## 自動化の範囲と限界

初期設定では、`.github/copilot-instructions.md` にContext Kit専用の指示を作成または追記します。
既存の指示は上書きせず、同じ専用ブロックを重複して追加しません。

この指示により、通常のCopilotが対応するログ・JSON・テキスト・Markdownを読む必要がある場合、`kit_read`の`safe`モードを優先的に自動選択します。
利用者が毎回「`kit_read`を使って」と入力する必要を減らせます。

ただし、ツールの選択はCopilotのモデル判断と実行許可にも左右されるため、すべての読み取りで必ず自動実行される保証はありません。
重要な作業ではツール実行欄を開き、`kit_read`や`kit_context`が実際に呼ばれたことを確認してください。

自動圧縮の対象になるのは、Context Kitのツールを通して読んだ対応ファイルです。
次の内容を自動で横取りして圧縮することはできません。

- Copilotの会話履歴全体
- Copilotが別のツールで直接読んだ内容
- ターミナルへ流れている途中で、ファイルへ保存されていない出力
- 対応対象外のソースコードや秘密情報を示すファイル

会話が長くなった場合は、Copilotへ`/context-handoff-save`を提案するよう指示します。
引き継ぎメモの作成後に利用者が新しいチャットを開き、`/context-handoff-resume`で再開します。
新しいチャットを自動で開いたり、既存の会話履歴を自動で削除したりはしません。

### 「初期設定を保存していません」と表示された場合

初期設定の途中で入力欄や選択画面を閉じた場合、ファイルを作成せずに終了します。
チャットには、どの段階で中断したかが表示されます。

- 作業フォルダがない場合は、「ファイル」から対象のフォルダを開きます。ファイルを1つ開いただけの状態では開始できません。
- 設計書がない場合は「あとで記入する」を選びます。
- 最後の確認では「設定する」を選びます。
- 再開するときは、チャットの「初期設定をもう一度開く」ボタンを押します。
- ボタンから開けない場合は、コマンドパレットで「Context Kit: 初期設定を始める」を実行します。

## 初期設定後の使い方

`@contextkit` は、初期設定と状況確認の専用窓口です。
一般的な相談、調査、実装は通常のCopilotエージェントチャットで行います。

### 状況を確認する

- `@contextkit 状況`：登録資料、出力記録、再確認が必要な資料を表示
- `@contextkit 圧縮状況`：処理前後の文字数・バイト数と参考差を表示
- コマンドパレットの「Context Kit: 用語集を開く」：用語集を編集
- コマンドパレットの「Context Kit: 設計書を開く」：登録済みの設計書を開く

### 接続を確認する

通常のCopilotエージェントチャットで、次のように依頼します。

```text
kit_contextで共通知識の一覧を見せてください。
```

ツール実行欄を開き、実際に `kit_context` が呼び出されて結果が返ることを確認してください。
もっともらしい文章が返るだけでは、接続確認にはなりません。

### 資料を指定して読む

一覧から必要な資料のIDを確認し、読む資料を限定します。

```text
kit_contextで action=read、id=glossary を指定し、用語集だけ読んでください。
```

資料の一覧を表示しただけでは、本文を出力済みとして記録しません。
「出力記録あり」は、AIが理解したこと、内容が正しいこと、人が承認したことを意味しません。

## 会話を引き継ぐ

初期設定で追加されるプロンプトを使い、作業の区切りで引き継ぎます。

1. `/context-handoff-save` を実行します。
2. `.context-kit/handoff.md` の確定事項、根拠、未確認事項を人が確認します。
3. 利用者が新しいチャットを開きます。
4. `/context-handoff-resume` を実行します。
5. 必要な原文だけを再確認して作業を続けます。

同じチャットに要約を追加するだけでは、元の会話履歴は減りません。
新しいチャットを開く操作は利用者が行います。

初期設定で用意されるプロンプトは次の6つです。

- `/context-handoff-save`：引き継ぎメモを作る
- `/context-handoff-resume`：新しいチャットで引き継ぎメモから再開する
- `/context-read`：指定した資料を整理して読む
- `/context-stats`：処理前後のサイズと参考差を確認する
- `/context-overview`：共通知識の登録状態を確認する
- `/context-question-propose`：未確認事項や矛盾の記録案を作る

## 共通知識の棚

初期設定では、プロジェクト直下の `project-context/` に資料の雛形と登録台帳を用意します。

```text
project-context/
  catalog.json          資料の場所・正式性・版・適用範囲
  overview.md           プロジェクト概要
  glossary.md           用語集
  requirements.md       要件・完了条件
  design/overview.md    設計書の入口
  decisions.md          決定と理由
  questions.md          未確認事項・矛盾
```

最初の状態は「検討中・未設定」です。
要件や設計を正式扱いにするかは利用者が決めます。
矛盾を自動で解決せず、確認が必要な内容として `questions.md` へ記録できます。

既存のMarkdown設計書は、コピーせずにワークスペース内の場所を `catalog.json` へ登録できます。
資料の内容、版、適用範囲が変わった場合は、再確認が必要な状態として表示します。

## 原文へ戻る仕組み

`kit_read` は資料を読み、保存版IDとSHA-256を返します。
`kit_source` は保存版IDを使い、必要な行だけを原文から取得します。

```text
context-kitのkit_readを使い、examples/requirements.mdをsafeで読んでください。
その後kit_sourceで原文の4〜6行を確認し、申込期限と例外条件を教えてください。
コードや設定は変更しないでください。
```

要点には `[S1]` のような識別子を付け、出典側に元ファイル、保存版ID、SHA-256、取得日時、原文行、短い引用を残せます。

```text
要点 D1：申込期限は金曜日。ただし祝日は前の営業日。[S1]
状態：原文参照済（意味の確認は別途必要）

S1：元ファイル、保存版ID、SHA-256、取得日時、原文4〜5行、短い引用
```

これは記録形式の例であり、実際の確認結果ではありません。
引用一致やハッシュ一致は、主張の正しさ、解釈、最新性、要約の完全性を保証しません。

## 圧縮する内容

- `safe`：ログの完全一致する連続行を回数付きで集約します。異なる行、エラー、警告はまとめません。
- JSON：文字列の外側にある空白だけを削除します。値、文字列内の空白、大きい整数、重複キーは変更しません。
- `.txt`、`.md`、`.jsonl`、`.ndjson`：本文を自動要約せず、保存版とページ取得を提供します。
- `preview`：ログの先頭、末尾、重要行の周辺だけを表示します。情報が落ちることと省略範囲を明示します。
- 上限を超える本文：途中で黙って切らず、本文を表示していないことと保存版IDを返します。

ソースコードのAST圧縮、自然文の学習モデル圧縮、任意コマンドの実行、Copilot通信の代理、認証変更は行いません。

## 圧縮状況の見方

拡張版では `@contextkit 圧縮状況` を使用します。
通常のCopilotでは `/context-stats`、または `kit_stats` を使用します。

表示する内容は次のとおりです。

- 資料そのものの処理前後の文字数・UTF-8バイト数
- 説明情報や原文再取得分を含めた参考差
- `preview`、本文未表示、ページ取得、集約した繰り返し行数
- 計測できていない古い記録の件数

本文を表示しなかったことを「100%圧縮」として扱いません。
短い入力では説明や根拠確認の追加分が上回り、参考差がマイナスになる場合があります。

この統計は、Copilot全体のトークン数、料金、回答品質、ハルシネーション低減率を測定するものではありません。

## 困ったとき

### ツールが表示されない

- VS Code 1.102以降のデスクトップ版か確認します。
- 対象のフォルダが信頼済みか確認します。
- MCPの信頼確認とツール実行許可を確認します。
- 組織のポリシーでMCPが制限されていないか確認します。
- 以前の手動MCP接続が残っている場合は、MCP一覧で古い `context-kit` 接続を停止します。

### 資料を読めない

次のファイルは安全上の理由から拒否される場合があります。

- ワークスペース外のファイル
- 認証情報や秘密情報を示す名前のファイル
- シンボリックリンクで外部を参照するファイル
- NULを含むバイナリファイル
- サイズ上限を超えるファイル
- UTF-8またはBOM付きUTF-16 LE/BEとして読めないファイル
- 読み取り中に内容やファイル実体が変わったファイル

必要な場合は、機密情報を除いた一時コピーを作成し、UTF-8またはBOM付きUTF-16へ変換してから読みます。

### 出力記録が壊れた

他の処理が動いていないことを確認し、CLIで次を実行します。

```sh
node src/cli.mjs purge --root "/absolute/path/to/project"
```

`purge` は保存版、出力記録、統計を削除しますが、元の資料は削除しません。
削除後は必要な資料を読み直してください。

### 停止したい

コマンドパレットで「Context Kit: このフォルダで停止する」を実行します。
接続は停止しますが、作成済みの資料は削除しません。

## 安全性と限界

- 拡張版は、設定済みの信頼された作業フォルダだけを対象にします。
- 内蔵MCPはPC内の `127.0.0.1` に一時ポートを開き、プロセスごとの認証トークンを使用します。
- 認証トークンを拡張の設定ファイルへ保存しません。
- VS CodeやCopilotの認証情報を取得する処理はありません。
- 独自の外部AI APIやクラウドサービスへ資料を送信しません。
- Copilotへ渡した資料は、通常のCopilot利用として扱われます。
- 秘密情報を完全自動で検出・削除する機能はありません。AIへ渡す前に内容を確認してください。
- `.gitignore` はGitへの混入を防ぐためのもので、暗号化、バックアップ停止、クラウド同期停止ではありません。
- 用語集、設計書、引き継ぎメモ、保存版は機密情報になり得ます。

キャッシュと引き継ぎメモをGitへ入れないため、初期設定は確認後に次の除外ルールを `.gitignore` へ追加します。

```gitignore
.context-kit-cache/
.context-kit/
```

## CLI方式で接続する

拡張版で初期設定した場合、この手動接続は不要です。
同じプロジェクトへ拡張版とCLI版を重複登録しないでください。

CLI版は、WSL、Remote SSH、Dev Container、ソースを改造する場合に使用します。
Node.js 20以上が必要です。実行時の追加パッケージと `npm install` は不要です。

### 1. キットを配置する

対象プロジェクトの `tools/copilot-context-kit/` へ、このリポジトリのファイルを配置します。
別の場所に置く場合は、設定生成時に対象プロジェクトの絶対パスを指定します。

リモート開発では、Node.jsとキットのパスがMCPサーバーを実行する側に存在する必要があります。

### 2. MCP設定を生成する

キットのフォルダで次を実行します。

```sh
node src/cli.mjs config --root "/absolute/path/to/project" --format vscode
```

このコマンドは設定JSONを表示するだけで、既存設定を変更しません。
表示された `context-kit` 項目を、対象プロジェクトの `.vscode/mcp.json` にある `servers` へ追加します。
既存ファイルを丸ごと上書きしないでください。

`mcpServers` 形式が必要な環境では、次を使用します。

```sh
node src/cli.mjs config --root "/absolute/path/to/project" --format portable
```

両方の形式を重複登録する必要はありません。

Node.jsが見つからない場合は、実行環境で次を確認します。

```sh
node --version
node -p "process.execPath"
```

### 3. プロンプトを配置する

`integration/prompts/` にある6ファイルを、対象プロジェクトの `.github/prompts/` へコピーします。
同名ファイルがある場合は上書きせず、内容を比較して統合します。

### 4. Git除外を設定する

CLI版は対象プロジェクトの `.gitignore` を自動変更しません。
対象プロジェクト直下の `.gitignore` に次を追加します。

```gitignore
.context-kit-cache/
.context-kit/
```

### 5. 接続を確認する

Copilotのエージェントチャットで `kit_read` と `kit_source` を明示して依頼し、ツール実行欄で実際の呼び出しを確認します。

## CLIを単体で確認する

`package.json` があるフォルダで次を実行します。

```sh
node --version
npm test
node src/cli.mjs read examples/sample.log
```

読み取り結果の先頭には、保存版の `snapshot_id` と `sha256` が表示されます。
表示された実際の値を使って原文を確認します。

```sh
node src/cli.mjs source <snapshot_id> --start-line 1 --end-line 8
node src/cli.mjs stats
node src/cli.mjs context --format text
```

`<snapshot_id>` は説明用です。山括弧を含めず、実際のIDへ置き換えてください。
呼び出し側で保持したSHA-256を `source` の `--sha256` へ指定すると、保存版との一致を外部期待値として確認できます。

## 費用と対応環境

- 拡張版はVS Code内蔵のNode実行環境を利用します。
- CLI版はNode.js 20以上を使用します。
- 独自APIキーは不要です。
- Copilotの利用は通常どおりCopilotの利用量に含まれます。
- 無料化や無制限化を行うツールではありません。
- 自動テストはmacOS、Ubuntu、WindowsのNode.js 20、22、24で実行しています。
- 実際のVS Code画面、Copilot接続、組織ポリシーは利用環境ごとに確認が必要です。

## 管理者・配布担当者向け

Marketplaceには公開せず、GitHub Releasesで `contextkit.vsix` を配布します。
利用者には `Source code.zip` ではなく、VSIXファイルを案内してください。

公開前の確認手順は `docs/FIRST-RELEASE.md`、安全性は `docs/SECURITY.md`、検証範囲は `docs/VERIFICATION.md`、既知のエラーは `docs/KNOWN-ERRORS.md` に記載しています。
READMEから別ページへ移動しなくても導入と基本利用が分かるようにしているため、これらは管理・監査時の補足資料として使用します。

テストとVSIX作成は次の順で行います。

```sh
npm test
python3 scripts/stage-extension.py
cd dist/extension
npx --yes @vscode/vsce@4.0.0 package --out ../contextkit.vsix
```

`scripts/stage-extension.py` は既存の出力先を削除しません。
再実行時は、内容を確認して以前の `dist/extension` を片付けるか、空の出力先を指定してください。

VSIXには `test/`、`node_modules/`、`.context-kit-cache/` を含めません。
公開前にファイル一覧とSHA-256を確認してください。

Windowsで長いパスを使用する場合、`LongPathsEnabled` の変更可否は組織の管理方針に従ってください。
組織管理端末では、MCP、拡張機能、ローカルポート、GitHub Copilotの利用制限も事前に確認してください。
