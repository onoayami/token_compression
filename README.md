# Copilot Context Compression Kit

GitHub Copilotで扱う会話や資料を整理し、必要な情報だけを使いやすくするVS Code拡張です。

主に次の2つを行います。

1. **送信前の自動圧縮**：macOSでは、Copilotへ送る直前の会話コンテキストから、繰り返しログや冗長なJSONなどを自動で圧縮できます。
2. **資料と引き継ぎの整理**：要件、設計書、用語集、決定事項、未確認事項を整理し、必要な原文へ戻れる状態でCopilotに渡します。

## 最初に知っておくこと

- 普段の相談や実装依頼は、いつものCopilot Chatで行います。
- `@contextkit` は初期設定と状態確認のための専用窓口です。
- macOSの自動圧縮を設定すると、毎回圧縮コマンドを入力する必要はありません。
- VS Code上の会話表示は消えません。Copilotへ送る直前のデータだけを圧縮します。
- ログ、JSON、同じ内容が続くツール出力には効果があります。
- 長い自然文をAIが意味要約する機能ではないため、文章によっては小さくなりません。
- 決定事項や未解決事項を次の会話へ引き継ぐ場合は、引き継ぎメモを使います。

## 必要な環境

### 基本機能

- VS Code 1.102以降のデスクトップ版
- GitHub Copilot
- 信頼済みのローカル作業フォルダ
- インストール用の `contextkit.vsix`

### macOSの自動圧縮

- macOS
- Visual Studio Code安定版
- Python 3.10以上
- 初回導入時のネット接続
- 約1GB弱の空き容量

自動圧縮はVisual Studio Code Insiders、VSCodiumなどの派生版、WSL、Remote SSH、Dev Container、ブラウザー版VS Codeには対応していません。

## インストール

1. VS Codeの拡張機能画面を開きます。
2. 画面右上の「…」を押します。
3. 「VSIXからのインストール」を選びます。
4. 受け取った `contextkit.vsix` を指定します。
5. 再読み込みを求められた場合はVS Codeを再読み込みします。

`Source code.zip` ではなく、`contextkit.vsix` を選んでください。

## プロジェクトの初期設定

1. 設定したいプロジェクトの**フォルダ**をVS Codeで開きます。
2. Copilot Chatで次のように入力します。

```text
@contextkit 初期設定
```

3. プロジェクトの目的を入力します。空欄でも進められます。
4. 既存のMarkdown設計書があれば選びます。なければ「あとで記入する」を選びます。
5. 作成される内容を確認し、「設定する」を選びます。
6. MCP接続の信頼確認が表示された場合は、内容を確認して承認します。

初期設定では不足している資料や設定だけを追加します。既存の資料、台帳、プロンプトは上書きしません。

### 初期設定を途中で閉じた場合

「初期設定は保存せずに終了しました」と表示された場合、ファイルは作成されていません。

- プロジェクトのフォルダを開いているか確認します。
- 設計書がなければ「あとで記入する」を選びます。
- 最後の確認で「設定する」を選びます。
- 再開するときは、もう一度 `@contextkit 初期設定` と入力します。
- チャットから開けない場合は、コマンドパレットで「Context Kit: 初期設定を始める」を実行します。

## macOSで送信前の自動圧縮を設定する

自動圧縮には、外部ソフトウェアのHeadroom `0.41.0` を使用します。HeadroomはVSIXには含まれておらず、利用者が同意した場合だけContext Kit専用の管理領域へインストールされます。Mac全体へグローバルインストールする方式ではありません。

1. コマンドパレットを開きます。
2. **Context Kit: 自動圧縮を設定** を実行します。
3. 表示された説明を読み、「インストールする」を選びます。
4. 導入後に **Headroomを認証** を選びます。
5. 表示されたURLを開き、デバイスコードを入力してGitHub認証を完了します。
6. 認証が成功すると自動圧縮が開始されます。

以後は、設定済みのVS Codeを起動すると自動圧縮も再開します。

Copilot Chatで `@contextkit /compress` を選んでも、同じ設定画面を開けます。

### 自動圧縮の仕組み

```text
Copilotへ送る会話コンテキスト
          ↓
Mac内のHeadroomプロキシ
          ↓
繰り返しログ・冗長なJSON・反復ツール出力を圧縮
          ↓
通常のGitHub Copilotへ送信
```

- プロキシは `127.0.0.1` のローカル接続だけを使用します。
- Copilotのモデル選択は変更しません。
- Context Kitは会話本文やOAuthトークンをログへ保存しません。
- Headroomのビーコン、利用統計送信、モデル自動ダウンロードは無効化して起動します。
- Context Kit専用の認証ファイルだけを使用し、既存のGitHub CLIトークンやmacOS Keychainを自動利用しないよう制限します。

HeadroomはGitHub Device FlowとCopilot Chat用OAuthクライアントIDを使う外部連携です。GitHub公式のContext Kit統合ではありません。会社や組織の端末で使う場合は、利用規約と組織ポリシーを確認してください。

### 自動圧縮でできること

- 同じログ行の繰り返しを回数付きで短くする
- JSONの不要な空白を減らす
- 反復するツール出力を短くする
- Copilotへ送る直前に自動で処理する

### 自動圧縮で保証しないこと

- 長い自然文を意味を理解して要約すること
- すべての会話で必ずトークンが減ること
- VS Codeに表示されている会話履歴を削除すること
- 回答品質や料金削減を保証すること
- 秘密情報を完全自動で検出して消すこと

### 停止と完全解除

- **Context Kit: 自動圧縮の状態**：稼働状態、認証状態、ポート競合を確認します。
- **Context Kit: 自動圧縮を停止（フェイルクローズ）**：Context Kitが起動したプロセスだけを停止します。設定は残るため、停止中はCopilot通信が迂回せず失敗する状態になります。
- **Context Kit: 自動圧縮を開始**：認証済みの自動圧縮を再開します。
- **Context Kit: 自動圧縮を完全解除**：VS Codeのプロキシ設定を元へ戻します。

完全解除後も、再利用できるように管理venvと専用認証ファイルは残ります。

## 普段の使い方

初期設定後は、通常のCopilot Chatへ普段どおり依頼します。

```text
このログを確認して、エラーの原因を調べてください。
```

```text
登録してある要件と設計書を確認して、この変更の影響を教えてください。
```

```text
kit_contextで共通知識の一覧を見せてください。
```

重要な作業では、ツール実行欄を開き、`kit_context`、`kit_read`、`kit_source` が実際に呼ばれたことを確認してください。

### 状態を確認する

- `@contextkit 状況`：登録資料と再確認の要否を表示
- `@contextkit 圧縮状況`：資料処理の文字数・バイト数を表示
- **Context Kit: 用語集を登録する**：既存のMarkdown用語集を選んで台帳へ登録
- **Context Kit: 設計書を登録する**：既存のMarkdown設計書を選んで台帳へ登録

`@contextkit 圧縮状況` は、Context Kitが読んだ資料の処理結果です。Headroom経由のCopilot全体のトークン数や料金を示すものではありません。

## 資料を整理する仕組み

初期設定では、プロジェクト内に次の資料を用意します。

```text
project-context/
  catalog.json          資料の登録台帳
  overview.md           プロジェクト概要
  glossary.md           用語集
  requirements.md       要件と完了条件
  design/overview.md    設計書の入口
  decisions.md          決定事項と理由
  questions.md          未確認事項と矛盾
```

最初は「検討中・未設定」の状態です。どの資料を正式な要件や設計として扱うかは利用者が決めます。

### 原文へ戻る

`kit_read` は資料を読み、整理した結果と保存版ID、SHA-256を返します。`kit_source` は保存版IDを使い、必要な行だけを原文から取得します。

```text
kit_readでrequirements.mdを読んでください。
重要な条件はkit_sourceで原文の行を確認してください。
```

これにより、短く整理した情報を使いながら、重要な数字や条件だけ原文へ戻って確認できます。

### 対応する整理方法

- ログ：完全一致する連続行を回数付きで集約
- JSON：文字列の外側にある不要な空白を削除
- テキスト・Markdown：勝手に意味要約せず、保存版とページ取得を提供
- preview：先頭、末尾、重要行周辺だけを表示し、省略を明示
- 大きすぎる本文：黙って途中で切らず、本文未表示と保存版IDを返す

## 長い会話を引き継ぐ

自動圧縮は送信前の構造圧縮であり、決定事項を長期保存する意味要約ではありません。会話が長くなったら引き継ぎメモを使います。

1. `/context-handoff-save` を実行します。
2. `.context-kit/handoff.md` の確定事項、根拠、未確認事項を確認します。
3. 新しいチャットを開きます。
4. `/context-handoff-resume` を実行します。
5. 必要な原文だけを再確認して作業を続けます。

新しいチャットを開く操作は利用者が行います。現在の会話履歴を自動削除する機能はありません。

初期設定では次のプロンプトも用意します。

- `/context-read`：指定した資料を整理して読む
- `/context-stats`：資料処理のサイズを確認する
- `/context-overview`：共通知識の登録状態を確認する
- `/context-question-propose`：未確認事項や矛盾の記録案を作る

## 安全性とプライバシー

- Context Kitの資料処理はPC内で行います。
- 資料を独自の外部AI APIへ送信しません。
- Copilotへ渡した内容は、通常のGitHub Copilot利用として送信されます。
- キャッシュはプロジェクト内の `.context-kit-cache/` に保存します。
- 引き継ぎメモは `.context-kit/` に保存します。
- 初期設定時に両方を `.gitignore` へ追加します。
- キャッシュは暗号化されません。クラウド同期やバックアップを自動停止する機能はありません。
- 秘密情報を完全自動で見つける機能はありません。Copilotへ渡す前に内容を確認してください。
- ワークスペース外のファイル、秘密情報を示す名前、危険なリンク、対応外の文字コードなどは拒否する場合があります。

## 困ったとき

### Context Kitのツールが表示されない

- VS Code 1.102以降か確認します。
- プロジェクトのフォルダが信頼済みか確認します。
- MCPの信頼確認とツール実行許可を確認します。
- 古い手動MCP接続がある場合は停止します。
- `@contextkit 初期設定` をもう一度実行します。

### 自動圧縮を開始できない

- macOSのVisual Studio Code安定版か確認します。
- Python 3.10以上が利用できるか確認します。
- 約1GB弱の空き容量があるか確認します。
- **Context Kit: Headroomを認証** を実行します。
- **Context Kit: 自動圧縮の状態** でポート競合を確認します。
- 「以前のContext Kitが起動したHeadroomが残っています」と表示された場合は、**Context Kit: 自動圧縮を開始** で引き継げます（VS Codeの再読み込みや拡張の更新後に起こります）。
- 「Context Kit以外のプロセスが…使用しています」と表示された場合、Context Kitはそのプロセスを終了しません。`lsof -nP -iTCP:8787 -sTCP:LISTEN` で確認して終了するか、設定 `contextkit.proxy.port` を空いているポートに変えてください。

### GitHubとの連携（Headroom認証）がうまくいかない

認証の流れ：
1. **Context Kit: Headroomを認証** を実行します。
2. 右下の通知の **コードをコピーしてGitHubを開く** を押します。
3. 開いたGitHubのページにコードを貼り付けて続行し、承認します。
4. VS Codeに戻って待つと、自動で完了し自動圧縮が始まります。

うまくいかないとき：

- **Context Kit: Headroomを認証** をもう一度実行するか、チャットで `@contextkit /auth` と入力します。未完了の認証は自動で中止され、新しいURLとコードで最初からやり直せます。
- 認証は15分で自動的に打ち切られます。失敗・期限切れの通知に表示される **Headroomを認証し直す** ボタンからもやり直せます。
- 自動圧縮の稼働中でも認証し直せます。成功すると自動圧縮を再起動して新しい認証を反映します。
- 別のVS Codeウィンドウで同じポートを使用している場合、Context Kitはそのプロセスを停止しません。

### 資料を読めない

次のファイルは拒否される場合があります。

- ワークスペース外のファイル
- 秘密情報を示す名前のファイル
- 外部を参照するシンボリックリンク
- 複数のハードリンクを持つファイル
- NULを含むバイナリ
- サイズ上限を超えるファイル
- UTF-8またはBOM付きUTF-16 LE/BEとして読めないファイル
- 読み取り中に変更されたファイル

必要な場合は、秘密情報を除いた一時コピーを作り、UTF-8またはBOM付きUTF-16へ変換してから読みます。

## 停止時に残るもの

- **Context Kit: このフォルダで停止する**：MCP接続だけを停止します。資料、キャッシュ、引き継ぎメモは削除しません。
- **Context Kit: 自動圧縮を完全解除**：HeadroomのVS Code設定を元へ戻します。管理venvと専用認証ファイルは残ります。

不要になった資料やキャッシュは、内容を確認して利用者が削除してください。

## CLI方式

拡張版で初期設定した場合、CLI方式は不要です。WSL、Remote SSH、Dev Container、またはソースを変更して使う場合だけ利用します。

必要な環境はNode.js 20以上です。追加パッケージのインストールは不要です。

設定例を表示するには次を実行します。

```sh
node src/cli.mjs config --root "/absolute/path/to/project" --format vscode
```

表示された `context-kit` の設定を、対象プロジェクトのMCP設定へ追加します。既存設定を丸ごと上書きしないでください。

CLI版では、対象プロジェクトの `.gitignore` に次を追加します。

```gitignore
.context-kit-cache/
.context-kit/
```

基本的な確認コマンドは次のとおりです。

```sh
npm test
node src/cli.mjs read examples/sample.log
node src/cli.mjs stats
node src/cli.mjs context --format text
```

## 管理者・配布担当者向け

- 配布するファイルは `contextkit.vsix` です。
- `Source code.zip` はインストール用ではありません。
- Marketplace公開を前提にせず、管理者が確認したVSIXを配布します。
- HeadroomはVSIXへ同梱しません。利用者の同意後にPyPIから導入します。
- 組織管理端末では、MCP、拡張機能、ローカルポート、Python、GitHub Device Flow、GitHub Copilotの利用可否を確認してください。
- 自動テストはUbuntu、Windows、macOSのNode.js 20、22、24で実行します。
- 実際のGitHub認証、Copilot通信、組織ポリシーは利用環境で確認してください。

テストとVSIX作成は次の順で行います。

```sh
npm test
python3 scripts/stage-extension.py
cd dist/extension
npx --yes @vscode/vsce@4.0.0 package --out ../contextkit.vsix
```

VSIXには `test/`、`node_modules/`、`.context-kit-cache/` を含めません。配布前にファイル一覧とSHA-256を確認してください。
